## Direct enquiries

The Contact form continues to prepare WhatsApp or email messages when the direct service is unconfigured. For direct delivery, the browser uses a Cloudflare Worker and its rate-limiting binding, a managed Turnstile widget, and Resend transactional email. The Worker checks the request origin, size, fields, acknowledgement, challenge hostname and action before requesting delivery to the configured recipient. Resend receives a stable idempotency key for retries of the same submission. The Worker stores no enquiries in a database and observability logs are disabled in its configuration.

1. Confirm `Gescard.a@richkey.ae` as the authorised recipient, who manages the inbox, and how long enquiries and provider records are kept. Use organisation-controlled Cloudflare and Resend accounts. The Worker and email service can start on their free plans within their current quotas. Check the published limits before activation. No paid plan is selected by this repository. [Cloudflare Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) · [Resend pricing](https://resend.com/pricing)
2. Create a managed Turnstile widget restricted to `gescardakiki.com`. In Resend, verify a sending domain or subdomain controlled by the site owner using Resend’s DNS instructions. Create a key scoped to sending. Use a verified address on that domain for `SENDER`. Visitor email goes in Reply-To. [Turnstile server validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) · [Resend domains](https://resend.com/docs/dashboard/domains/introduction)
3. From `website/`, deploy using Wrangler with `--config worker/wrangler.toml`. Set `TURNSTILE_SECRET`, `RESEND_API_KEY` and `SENDER` through Wrangler’s `secret put` command or the Cloudflare dashboard. The allowed origin and recipient are declared in the Worker configuration. Do not add secret values to the frontend, repository or build output. [Worker secrets](https://developers.cloudflare.com/workers/configuration/secrets/) · [Rate-limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
4. Set the public build variables `NEXT_PUBLIC_ENQUIRY_ENDPOINT` to the deployed HTTPS Worker URL ending in `/enquiry` and `NEXT_PUBLIC_TURNSTILE_SITE_KEY` to the widget’s public key. Re-export and review the static site. Check the privacy wording for the configured providers, data transfers and agreed retention.
5. With the recipient’s agreement, send a clearly labelled test using a project enquiry from the live website. Confirm actual receipt in the business inbox and check Reply-To, then test a missing required field, a stale challenge and a failure path in a test environment. Provider acceptance is the signal for the on-site confirmation. Inbox receipt is a separate release check. [Resend idempotency](https://resend.com/docs/dashboard/emails/idempotency-keys)

## Google Analytics 4

Enable only after Gescard approves the measurement plan. Create a GA4 web stream for the custom domain, disable Enhanced Measurement so GA does not duplicate or expand the explicit event set, and keep advertising features disabled. Set `NEXT_PUBLIC_GA_MEASUREMENT_ID` to the approved stream ID and re-export. The preference UI and Google tag are absent from builds without an ID.

Visitors can allow or decline analytics with equally prominent controls. The tag loads after acceptance and uses basic Consent Mode with advertising permissions denied. Cookie settings are accessible in the footer and Privacy Policy. The preference expires after 180 days. Withdrawal stops reporting and clears the analytics cookies available on the current domain. Events omit form fields, phone and email addresses, WhatsApp message text, URL queries and fragments. Referral data is limited to the referring origin. [Google Consent Mode](https://developers.google.com/tag-platform/security/concepts/consent-mode) · [ICO storage and access guidance](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/what-are-storage-and-access-technologies/)

| Event | When recorded |
| --- | --- |
| `page_view`, `project_view` | A page or development is viewed, including navigation within the site |
| `generate_lead` | The enquiry service confirms provider acceptance of a validated submission |
| `whatsapp_click` | A WhatsApp link or the form’s WhatsApp continuation is used |
| `consultation_click`, `project_enquiry_click` | The visitor opens Contact or chooses a project enquiry channel |
| `telephone_click`, `email_click` | The visitor opens a phone or email link |
| `gallery_interaction` | A gallery is opened or a photo is selected |
| `youtube_outbound`, `instagram_outbound` | The visitor follows a link to the external platform |

Use Realtime and DebugView to check a consented session. Verify declining and withdrawing with the browser Network panel, then exercise the link and gallery events. Verify a successful test enquiry creates one `generate_lead` event. Register `project_slug`, `channel` and `action` as event-scoped custom dimensions if you need them in Explorations. Mark `generate_lead` and `whatsapp_click` as separate key events. The former counts provider-accepted enquiries, and the latter measures intent to start a conversation.

In GA4, see Reports → Acquisition → Traffic acquisition for sources and Reports → Engagement → Pages and screens for visits and project paths. Use Events or Explorations to compare enquiry actions, galleries and consented sessions. Use the session key event rate with a named event for conversion reporting. For the number of received leads and sales-qualified contacts, use the business inbox or approved CRM. Consent and blocking affect analytics coverage.
